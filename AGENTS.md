# Repository Agent Instructions

Read and follow the existing project documentation before making changes. The repository's established canon, technical scope, source hierarchy, protected files, and approval workflow take precedence over generic guidance.

## Living Story Method integration

For any fiction, chapter, outline, character, dialogue, quest narrative, cutscene, lore, or story-planning task, read `WRITING_METHOD/README.md`, then apply `WRITING_METHOD/LSM_MASTER_PROTOCOL.md` and `WRITING_METHOD/PROJECT_ADAPTER.md`.

These files are a craft framework, not a replacement for this repository's existing rules. Read and obey project-specific instructions, canon/source authority, continuity records, protected-content rules, and approval workflow first. The project adapter identifies the relevant boundaries. For code-only tasks, use the method only where narrative content is affected; do not change software behavior merely to satisfy prose guidance.

The LSM specifically requires deliberate POV selection and controlled POV switches, distinct character motives and voices, clear scene goals and consequences, physical staging, world/system consistency, continuity and knowledge tracking, and revision before presenting finished prose. Do not present checklists instead of the requested story. Do not promote drafts or plans to canon unless the project rules authorize it.

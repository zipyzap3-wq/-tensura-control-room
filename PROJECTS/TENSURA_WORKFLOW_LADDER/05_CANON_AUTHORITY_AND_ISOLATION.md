# Canon Authority and Clean-Slate Isolation
## Authority hierarchy
1. Explicit user-approved project decisions and canon records.
2. Approved chapters in this project.
3. Project continuity ledgers derived from approved material.
4. Tensura Volumes 6-7 source text for original-source event fidelity.
5. Verified research notes and labeled inference.
6. Working plans, outlines and unapproved drafts.
7. Assistant speculation, never canon.

Source canon and project canon are distinct. Source text establishes what happened in the original; project canon records what the user approves for this adaptation.

## Clean-slate boundary
This project begins with no inherited story canon. The old Gobta/Take Two project remains separate. Its chapters, character sheets, plot decisions, AU developments, powers, relationship states and continuity markers are not facts here. Reusable craft methods may be adapted separately and stripped of story assumptions.

## Status labels
SOURCE FACT; PROJECT CANON; WORKING DECISION; INFERENCE; UNKNOWN; DRAFT; REJECTED. Never silently promote inference, outline, assistant invention or draft into canon.

## Approval boundaries
Explicit approval is required before canon promotion, overwriting/deleting existing project files, changing approved canon/designs, publishing/merging protected work, changing source originals, or changing user-approved operating boundaries. User authorization in this conversation covers initial project construction inside this repository's main branch and import of requested Volume 6-7 source files. It does not authorize story canon creation or chapter drafting.

# Self-Evolution and Preventive Improvement Loop
This is a manual ChatGPT review-and-update process, not an agent or autonomous system.

## Trigger points
After GitHub first review (09), independent second audit (11), path-map verification (12), user feedback, or a repeated error.

## Improvement cycle
1. Observe an actual error, missed step, repeated weakness or confusing instruction.
2. Classify: story, source reading, character/knowledge, continuity, prose, navigation, workflow bypass, synchronization or approval boundary.
3. Identify root cause. "Be more careful" is not a useful diagnosis.
4. Write a specific checkable preventive rule.
5. Place it where it will be encountered before the failure: master ladder, stage file, template, dossier or review checklist.
6. Regression-check for conflicts, needless repetition and new failure modes.
7. Version according to branding standard.
8. Record evidence, reason, changed files and future validation in improvement register/changelog.

Never change story canon through this loop. Do not rewrite approved premise. Do not add vague duplicate checklists. Workflow improvement is not complete until a concrete rule and placement are recorded.
